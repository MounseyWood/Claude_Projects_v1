01 · Bind

The image becomes geometry

A regular grid of particles is laid over the bitmap. Each particle keeps the UV it had at rest, so the texture is welded to the mesh: move a particle and the pixels around it move with it. Nothing re-samples the image — the GPU interpolates within each triangle.

02 · Fix

A pin is a constraint, not a special case

“Fixed” means inverse mass w = 0: the solver computes a correction and then multiplies it by zero. That is the same attachment constraint the pointer uses, taken to the limit α → 0. Your drag is the same constraint, softer and mobile — and because the multiplier is a force, the grip is given a strength of 1.2 N per particle. Yank hard and the cloth slips through your fingers instead of stretching without limit.

03 · Solve

Compliance replaces stiffness

Plain PBD gets stiffer as you add iterations. XPBD carries a Lagrange multiplier per constraint and a compliance α in metres per newton, scaled by the step to ã, so canvas stays canvas whatever the frame rate.

ã = α / Δt² Δλ = ( −C − ãλ ) / ( ∑ wᵢ|∇ᵢC|² + ã ) Δxᵢ = wᵢ Δλ ∇ᵢC
04 · Read

The circles are strain gauges

The printed dots start as circles. Pull the sheet and they become ellipses — the long axis points along the stretch, exactly as a strain ellipse does in mechanics. Switch to the strain view to see the same field as colour.

Solver after Macklin, Müller & Chentanez, “XPBD: position-based simulation of compliant constrained dynamics” (MIG 2016), stepped as in Macklin et al., “Small steps in physics simulation” (SCA 2019).
Compliance presets are per-constraint values tuned by eye for this mesh, not measured from real fabric; because ã = α/Δt² is weighed against the particle masses, the same number reads differently at another mesh resolution. Images you drop are read locally and never uploaded.
